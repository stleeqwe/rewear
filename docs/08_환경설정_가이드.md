### 1.2 변수별 용도 및 사용 위치

| 변수 | 용도 | 사용 위치 |
|------|------|-----------|
| `SUPABASE_URL` | Supabase 프로젝트 API 엔드포인트 | Flutter 앱 (`supabase_client.dart`) |
| `SUPABASE_ANON_KEY` | 클라이언트용 공개 키 (RLS 적용) | Flutter 앱 (`supabase_client.dart`) |
| `SUPABASE_SERVICE_ROLE_KEY` | 서버용 관리 키 (RLS 우회) | Edge Functions 전용. 절대 클라이언트 노출 금지 |
| `GEMINI_API_KEY` | Gemini Flash API 인증 키 | Edge Function (`ai-review`) |
| `CLOUDINARY_CLOUD_NAME` | Cloudinary 클라우드 이름 | Edge Function (`process-image`) |
| `CLOUDINARY_API_KEY` | Cloudinary API 인증 키 | Edge Function (`process-image`) |
| `CLOUDINARY_API_SECRET` | Cloudinary API 시크릿 | Edge Function (`process-image`) |
| `FIREBASE_PROJECT_ID` | Firebase 프로젝트 식별자 | Edge Function (`push-notify`), Flutter 앱 |
| `KAKAO_APP_KEY` | 카카오 네이티브 앱 키 | Flutter 앱 (카카오 로그인 SDK) |
| `KAKAO_REST_API_KEY` | 카카오 REST API 키 | Edge Function (카카오 사용자 정보 조회) |

### 1.3 보안 등급 분류

| 등급 | 변수 | 설명 |
|------|------|------|
| **PUBLIC** | `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `KAKAO_APP_KEY`, `FIREBASE_PROJECT_ID` | 클라이언트 앱에 포함 가능. RLS/SDK 정책으로 보호 |
| **SECRET** | `SUPABASE_SERVICE_ROLE_KEY`, `GEMINI_API_KEY`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`, `KAKAO_REST_API_KEY` | Edge Function에서만 사용. 클라이언트에 절대 노출 금지 |

## 2. 서비스별 설정 가이드

### 2.1 Supabase

Supabase는 LEAFIT의 핵심 백엔드입니다. PostgreSQL, Auth, Realtime, Storage, Edge Functions를 통합 제공합니다.

**프로젝트 생성**

```bash
# 1. Supabase CLI 설치
npm install -g supabase

# 2. 로그인
supabase login

# 3. 프로젝트 초기화 (로컬)
supabase init

# 4. Supabase Dashboard에서 프로젝트 생성
#    https://supabase.com/dashboard → New Project
#    - Organization: LEAFIT
#    - Project name: leafit-dev / leafit-staging / leafit-prod
#    - Database password: 강력한 비밀번호 생성 후 안전하게 보관
#    - Region: Northeast Asia (ap-northeast-1) — 한국 서비스 최적

# 5. 로컬-리모트 연결
supabase link --project-ref <project-id>
```

**Auth 설정 (Supabase Dashboard)**

```
Authentication → Providers:
  ├── Kakao
  │   ├── Client ID: {KAKAO_REST_API_KEY}
  │   ├── Client Secret: (카카오 개발자 콘솔에서 발급)
  │   └── Redirect URL: Supabase에서 자동 생성된 콜백 URL
  └── Apple
      ├── Client ID: (Apple Developer에서 Services ID 생성)
      ├── Secret Key: (Apple Developer에서 Key 생성)
      └── Redirect URL: Supabase에서 자동 생성된 콜백 URL
```

**Edge Function 시크릿 등록**

```bash
# Supabase Edge Functions에서 사용하는 시크릿 변수 등록
supabase secrets set GEMINI_API_KEY=AIzaSy...
supabase secrets set CLOUDINARY_CLOUD_NAME=leafit
supabase secrets set CLOUDINARY_API_KEY=123456789012345
supabase secrets set CLOUDINARY_API_SECRET=abcdefghijklmnopqrstuvwx
supabase secrets set FIREBASE_PROJECT_ID=leafit-prod
supabase secrets set KAKAO_REST_API_KEY=abcdef...

# 등록된 시크릿 확인
supabase secrets list
```

**Realtime 활성화**

```
Database → Replication:
  ├── messages 테이블: INSERT 이벤트 활성화 (채팅 실시간)
  └── trades 테이블: UPDATE 이벤트 활성화 (거래 상태 실시간)
```

**Storage 버킷 설정**

```
Storage → New Bucket:
  ├── 이름: item-photos
  ├── Public: Yes (CDN URL로 직접 접근)
  ├── File size limit: 10MB
  └── Allowed MIME types: image/jpeg, image/png, image/webp
```

### 2.2 Firebase

Firebase는 푸시 알림(FCM), 크래시 리포팅(Crashlytics), 사용자 분석(Analytics)에 사용됩니다.

**프로젝트 생성**

```bash
# 1. Firebase CLI 설치
npm install -g firebase-tools

# 2. 로그인
firebase login

# 3. Firebase Console에서 프로젝트 생성
#    https://console.firebase.google.com → Add Project
#    - Project name: leafit-dev / leafit-prod
#    - Google Analytics: 활성화

# 4. FlutterFire CLI로 Flutter 앱 등록
dart pub global activate flutterfire_cli
flutterfire configure --project=leafit-prod
```

`flutterfire configure` 실행 시 자동 생성되는 파일:

| 파일 | 설명 |
|------|------|
| `lib/firebase_options.dart` | 플랫폼별 Firebase 설정 (자동 생성, 직접 수정 금지) |
| `android/app/google-services.json` | Android Firebase 설정 |
| `ios/Runner/GoogleService-Info.plist` | iOS Firebase 설정 |

**FCM 설정**

```
Firebase Console → Cloud Messaging:
  ├── Android: google-services.json이 자동 처리
  └── iOS:
      ├── APNs Authentication Key (.p8) 업로드
      ├── Key ID 입력
      └── Team ID 입력
```

**Crashlytics 활성화**

```
Firebase Console → Crashlytics → 시작하기
```

```dart
// main.dart에서 초기화
void main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform);
  FlutterError.onError = FirebaseCrashlytics.instance.recordFlutterFatalError;
  runApp(const ProviderScope(child: LeafitApp()));
}
```

### 2.3 Cloudinary

Cloudinary는 이미지 리사이징, WebP 변환, CDN을 담당합니다. Edge Function에서 서버사이드로 호출합니다.

**계정 설정**

```
1. https://cloudinary.com → Sign Up (무료 티어: 월 25GB 대역폭)
2. Dashboard에서 확인:
   - Cloud name → CLOUDINARY_CLOUD_NAME
   - API Key → CLOUDINARY_API_KEY
   - API Secret → CLOUDINARY_API_SECRET
```

**이미지 변환 프리셋 생성**

```
Settings → Upload Presets → Add Upload Preset:
  ├── 이름: leafit_item
  ├── Folder: items/
  ├── Transformations:
  │   ├── 원본: w_1080, q_auto, f_webp
  │   └── 썸네일: w_400, h_400, c_fill, q_auto, f_webp
  └── Eager Transformations: 업로드 시 즉시 썸네일 생성
```

**Edge Function에서의 사용 패턴**

```typescript
// supabase/functions/process-image/index.ts
import { v2 as cloudinary } from 'cloudinary';

cloudinary.config({
  cloud_name: Deno.env.get('CLOUDINARY_CLOUD_NAME'),
  api_key: Deno.env.get('CLOUDINARY_API_KEY'),
  api_secret: Deno.env.get('CLOUDINARY_API_SECRET'),
});

// Storage URL → Cloudinary 업로드 → 원본 + 썸네일 URL 반환
const result = await cloudinary.uploader.upload(storageUrl, {
  upload_preset: 'leafit_item',
});
```

### 2.4 Gemini Flash

Gemini Flash는 옷 사진 AI 검수에 사용됩니다. 건당 약 $0.001로 비용 효율적입니다.

**API 키 발급**

```
1. https://aistudio.google.com → Get API Key
2. Create API Key → 프로젝트 선택 또는 새 프로젝트 생성
3. 생성된 키 → GEMINI_API_KEY
```

**Edge Function에서의 사용 패턴**

```typescript
// supabase/functions/ai-review/index.ts
const GEMINI_URL =
  'https://generativelanguage.googleapis.com/v1beta/models/gemini-2.0-flash:generateContent';

const response = await fetch(
  `${GEMINI_URL}?key=${Deno.env.get('GEMINI_API_KEY')}`,
  {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      contents: [{
        parts: [
          {
            text: '이 이미지가 의류 사진인지, 판매 가능한 상태인지 판단해주세요. ' +
                  '합격/불합격 여부와 사유를 JSON으로 응답해주세요.',
          },
          { inline_data: { mime_type: 'image/jpeg', data: base64Image } },
        ],
      }],
    }),
  },
);
```

**비용 예측**

| 구분 | 수치 |
|------|------|
| 건당 비용 | ~$0.001 |
| 300명 x 월 10건 | ~$3/월 |

### 2.5 Kakao

카카오 로그인은 한국 시장에서 필수적인 소셜 로그인입니다.

**앱 등록**

```
1. https://developers.kakao.com → 내 애플리케이션 → 애플리케이션 추가
   - 앱 이름: LEAFIT
   - 사업자명: (사업자 정보)

2. 앱 키 확인:
   - 네이티브 앱 키 → KAKAO_APP_KEY (Flutter 앱)
   - REST API 키 → KAKAO_REST_API_KEY (Edge Function)

3. 플랫폼 등록:
   - Android: 패키지명 + 키 해시
   - iOS: 번들 ID

4. 카카오 로그인 활성화:
   - 제품 설정 → 카카오 로그인 → 활성화
   - 동의항목: 닉네임(필수), 프로필 사진(선택)

5. Redirect URI 등록:
   - Supabase Auth 콜백 URL 등록
   - https://xxxxx.supabase.co/auth/v1/callback
```

**Flutter 네이티브 설정 (Android)**

```xml
<!-- android/app/src/main/AndroidManifest.xml -->
<activity android:name="com.kakao.sdk.flutter.AuthCodeCustomTabsActivity">
  <intent-filter>
    <action android:name="android.intent.action.VIEW" />
    <category android:name="android.intent.category.DEFAULT" />
    <category android:name="android.intent.category.BROWSABLE" />
    <data android:scheme="kakao{KAKAO_APP_KEY}" android:host="oauth" />
  </intent-filter>
</activity>
```

**Flutter 네이티브 설정 (iOS)**

```xml
<!-- ios/Runner/Info.plist -->
<key>CFBundleURLTypes</key>
<array>
  <dict>
    <key>CFBundleURLSchemes</key>
    <array>
      <string>kakao{KAKAO_APP_KEY}</string>
    </array>
  </dict>
</array>
<key>LSApplicationQueriesSchemes</key>
<array>
  <string>kakaokompassauth</string>
  <string>kakaolink</string>
</array>
```

| 항목 | dev | staging | prod |
|------|-----|---------|------|

## 4. Flutter 환경 설정 방식

### 4.1 `--dart-define` 방식

빌드 시 환경 변수를 개별 주입합니다. CI/CD에서 시크릿 매니저와 연동할 때 적합합니다.

```bash
# 개발 환경
flutter run \
  --dart-define=ENV=dev \
  --dart-define=SUPABASE_URL=http://localhost:54321 \
  --dart-define=SUPABASE_ANON_KEY=eyJ... \
  --dart-define=KAKAO_APP_KEY=abc...

# 프로덕션 빌드
flutter build apk \
  --dart-define=ENV=prod \
  --dart-define=SUPABASE_URL=https://xxxxx.supabase.co \
  --dart-define=SUPABASE_ANON_KEY=eyJ... \
  --dart-define=KAKAO_APP_KEY=abc...
```

### 4.2 `--dart-define-from-file` 방식 (권장)

변수가 많을 때 JSON 파일에서 일괄 로드합니다. 로컬 개발에서 편리합니다.

**환경 파일 생성**

```json
// .env.dev.json (Git에 포함하지 않음)
{
  "ENV": "dev",
  "SUPABASE_URL": "http://localhost:54321",
  "SUPABASE_ANON_KEY": "eyJ...",
  "KAKAO_APP_KEY": "abc..."
}
```

```json
// .env.prod.json
{
  "ENV": "prod",
  "SUPABASE_URL": "https://xxxxx.supabase.co",
  "SUPABASE_ANON_KEY": "eyJ...",
  "KAKAO_APP_KEY": "abc..."
}
```

**실행 명령어**

```bash
# 개발
flutter run --dart-define-from-file=.env.dev.json

# 스테이징
flutter run --dart-define-from-file=.env.staging.json

# 프로덕션 빌드
flutter build apk --dart-define-from-file=.env.prod.json
flutter build ios --dart-define-from-file=.env.prod.json
```

### 4.3 Dart 코드에서 환경 변수 접근

```dart
// lib/core/env.dart
class Env {
  static const String environment =
      String.fromEnvironment('ENV', defaultValue: 'dev');
  static const String supabaseUrl =
      String.fromEnvironment('SUPABASE_URL');
  static const String supabaseAnonKey =
      String.fromEnvironment('SUPABASE_ANON_KEY');
  static const String kakaoAppKey =
      String.fromEnvironment('KAKAO_APP_KEY');

  static bool get isDev => environment == 'dev';
  static bool get isStaging => environment == 'staging';
  static bool get isProd => environment == 'prod';
}
```

### 4.4 main.dart 초기화 순서

```dart
// lib/main.dart
import 'package:flutter/material.dart';
import 'package:flutter_riverpod/flutter_riverpod.dart';
import 'package:supabase_flutter/supabase_flutter.dart';
import 'package:firebase_core/firebase_core.dart';
import 'core/env.dart';
import 'firebase_options.dart';
import 'app.dart';

void main() async {
  // 1. Flutter 엔진 초기화
  WidgetsFlutterBinding.ensureInitialized();

  // 2. Firebase 초기화 (FCM, Crashlytics, Analytics)
  await Firebase.initializeApp(
    options: DefaultFirebaseOptions.currentPlatform,
  );

  // 3. Crashlytics 설정 (prod/staging만)
  if (!Env.isDev) {
    FlutterError.onError =
        FirebaseCrashlytics.instance.recordFlutterFatalError;
  }

  // 4. Supabase 초기화
  await Supabase.initialize(
    url: Env.supabaseUrl,
    anonKey: Env.supabaseAnonKey,
  );

  // 5. Riverpod ProviderScope로 앱 시작
  runApp(
    const ProviderScope(
      child: LeafitApp(),
    ),
  );
}
```

## 5. Supabase 마이그레이션 명령어

### 5.1 로컬 개발 서버

```bash
# Supabase 로컬 서버 시작 (Docker 필요)
supabase start

# 로컬 서버 상태 확인
supabase status
# → API URL: http://localhost:54321
# → anon key: eyJ...
# → service_role key: eyJ...

# 로컬 서버 중지
supabase stop
```

### 5.2 마이그레이션 관리

```bash
# 새 마이그레이션 파일 생성
supabase migration new users_items
# → supabase/migrations/20260311000000_users_items.sql 생성

# 로컬 DB에 마이그레이션 적용
supabase db push

# 현재 마이그레이션 상태 확인
supabase migration list

# 로컬 DB 초기화 (마이그레이션 + 시드 재적용)
supabase db reset
```

### 5.3 리모트 환경 배포

```bash
# 리모트 프로젝트 연결
supabase link --project-ref <project-id>

# 리모트 DB에 마이그레이션 적용
supabase db push

# 현재 리모트 DB와 로컬 마이그레이션 차이 확인
supabase db diff
```

### 5.4 Edge Function 배포

```bash
# 단일 함수 로컬 테스트
supabase functions serve ai-review --no-verify-jwt

# 단일 함수 리모트 배포
supabase functions deploy ai-review

# 전체 함수 리모트 배포
supabase functions deploy

# 함수 로그 확인
supabase functions logs ai-review
```

### 5.5 시드 데이터


### 5.6 마이그레이션 파일 구조

```
supabase/migrations/
├── 001_users_items.sql
│   ├── users 테이블 (프로필, 리프 잔액, 뱃지, 설정)
│   ├── items 테이블 (옷 정보, 상태 머신)
│   ├── item_photos 테이블 (사진 URL, 정렬)
│   ├── RLS 정책 (users: 누구나 읽기/본인 수정, items: active 공개/본인 쓰기)
│   ├── 인덱스 (status, category, user_id, GIN 한글 텍스트 검색)
│   └── DB Function: grant_leaf_for_upload, signup_bonus
│
├── 002_trades_messages.sql
│   ├── trades 테이블 (거래 상태 머신: chatting→reserved→completed)
│   ├── messages 테이블 (채팅 메시지: text/image/system/appointment)
│   ├── RLS 정책 (거래 참여자 seller/buyer만 접근)
│   ├── Realtime 활성화 (messages INSERT, trades UPDATE)
│   └── DB Function: complete_swap (리프 차감 + 상태 변경 원자적 트랜잭션)
│
├── 003_leaf_wishlist_reports.sql
│   ├── leaf_transactions 테이블 (리프 입출금 이력: +1/-1)
│   ├── wishlist 테이블 (찜 목록: user_id + item_id UNIQUE)
│   ├── reports 테이블 (신고: 대상 유형/ID, 사유, 처리 상태)
│   ├── RLS 정책 (본인 데이터만 접근, leaf_transactions 쓰기는 SECURITY DEFINER만)
│   └── DB Function: process_invite (양쪽 리프 지급), donate_item
│
└── 004_notifications_sponsors.sql
    ├── notifications 테이블 (알림: 유형, 제목, 참조, 읽음)
    ├── sponsored_items 테이블 (광고: 브랜드, 노출/클릭 카운트, 기간)
    ├── RLS 정책 (알림: 본인만 접근, 광고: 활성 기간 공개 읽기)
    └── 인덱스 (알림: user_id + is_read, 광고: is_active + 기간 범위)
```

## 6. 모니터링 도구

### 6.1 Firebase Crashlytics

앱 크래시를 실시간으로 수집하고 분석합니다.

| 항목 | 설명 |
|------|------|
| 용도 | Flutter 앱 런타임 크래시 리포트 |
| 수집 대상 | Dart 예외, 네이티브 크래시, ANR |
| 대시보드 | Firebase Console → Crashlytics |
| 알림 | 새로운 크래시 유형 발생 시 이메일/Slack 알림 설정 가능 |
| 환경 | staging + prod에서만 활성화. dev에서는 비활성 |

**설정 코드**

```dart
// main.dart
FlutterError.onError = FirebaseCrashlytics.instance.recordFlutterFatalError;

// 비동기 에러 캐치
PlatformDispatcher.instance.onError = (error, stack) {
  FirebaseCrashlytics.instance.recordError(error, stack, fatal: true);
  return true;
};
```

**핵심 모니터링 지표**

| 지표 | 목표 |
|------|------|
| Crash-free users rate | 99.5% 이상 |
| 크래시 유형별 발생 빈도 | 신규 크래시 24시간 내 대응 |
| 영향받는 유저 수 | 1% 미만 |
| 크래시 분포 | 기기/OS 버전별 추적 |

### 6.2 Firebase Analytics

유저 행동 데이터를 수집하여 서비스 개선에 활용합니다.

| 항목 | 설명 |

## 7. 개발 환경 초기 설정 체크리스트

프로젝트에 새로 합류하는 개발자가 따라야 할 순서입니다.

```
[ ] 1. Flutter SDK 설치 (3.5.0 이상)
      → flutter doctor 로 환경 확인

[ ] 2. 레포지토리 클론
      → git clone <repo-url>
      → cd leafit

[ ] 3. 패키지 설치
      → flutter pub get

[ ] 4. 코드 생성
      → dart run build_runner build --delete-conflicting-outputs

[ ] 5. 환경 변수 파일 생성
      → .env.dev.json 파일을 팀에서 공유받아 프로젝트 루트에 배치
      → .gitignore에 등록 확인

[ ] 6. Supabase 로컬 서버 시작 (선택)
      → Docker Desktop 실행 확인
      → supabase start
      → supabase db reset (마이그레이션 + 시드)

[ ] 7. Firebase 설정
      → flutterfire configure --project=leafit-dev

[ ] 8. iOS 설정 (macOS)
      → cd ios && pod install && cd ..
      → Xcode에서 Signing & Capabilities 확인

[ ] 9. 실행
      → flutter run --dart-define-from-file=.env.dev.json

[ ] 10. DevTools 확인
       → Flutter DevTools에서 앱 정상 연결 확인
```

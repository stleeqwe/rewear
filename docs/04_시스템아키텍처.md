## 2. 기술 스택 (Tech Stack)

| 레이어 | 기술 | 선정 이유 |
|--------|------|-----------|
| 모바일 앱 | Flutter (Dart) | 자체 렌더링 커스텀 UI, iOS/Android 픽셀 동일 |
| 상태 관리 | Riverpod | 컴파일 타임 안전성, 비동기, Flutter 공식 권장 |
| 라우팅 | go_router | 선언적 라우팅, 딥링크 지원 |
| 백엔드 | Supabase | PostgreSQL ACID 트랜잭션, 실시간, 인증, 스토리지 통합 |
| AI 검수 | Gemini Flash | 건당 ~$0.001, 1초 응답, 이미지 분류 최적 |
| 이미지 CDN | Cloudinary | 자동 리사이징, WebP 변환, 썸네일, CDN |
| 푸시 알림 | FCM | Flutter 네이티브 지원, iOS/Android 통합 |
| 분석 | Firebase Analytics | 유저 행동 추적, 이벤트 퍼널 |

### Flutter 채택 이유 (vs React Native + Expo)

LEAFIT의 "Electric Garden" 디자인 시스템을 네이티브 성능으로 구현하기 위한 최적의 선택

- 🎨 **자체 렌더링 엔진** — Lime glow, 파티클 애니메이션, 커스텀 뱃지 등 브랜드 UI를 네이티브 성능으로 구현
- 📱 **픽셀 동일 브랜드 경험** — iOS/Android에서 픽셀 단위로 동일한 Electric Garden 디자인 보장
- ✨ **내장 그래픽 API** — CustomPainter, Shader, AnimationController 등 프레임워크 내장 그래픽 도구
- ⚡ **네이티브 성능** — Dart AOT 컴파일로 브릿지 오버헤드 없는 순수 네이티브 실행

### Supabase 채택 이유 (vs Firebase)

- **ACID 트랜잭션** — PostgreSQL 기반으로 리프 잔액 정합성을 DB Function에서 원자적으로 보장
- **Row Level Security** — 클라이언트가 직접 DB에 접근해도 RLS 정책으로 데이터 보안 유지
- **SQL 자유도** — 복잡한 필터, 정렬, 검색, JOIN 쿼리를 SQL로 자유롭게 작성
- **Edge Functions** — Deno 기반 서버리스 로직으로 AI 검수, 푸시, 이미지 처리 구현

### Gemini Flash 채택 이유 (vs Claude Vision)

| 항목 | 내용 |
|------|------|
| 태스크 특성 | 고도 추론 불필요 — 구조화된 이미지 분류 |
| 비용 | 건당 ~$0.001 (Claude 대비 5~10배 저렴) |
| 응답 속도 | 1초 이내 → 유저 대기 UX 최적 |
| 월 비용 | 300명 x 10건 = ~$3/월 (사실상 무료) |

## 4. 데이터베이스 (Database)

### ERD 관계도

| From | Relation | To |
|------|----------|-----|
| users | 1:N | items, leaf_transactions, notifications, reports |
| items | 1:N | item_photos |
| items | 1:1 | trades (item_id) |
| trades | N:1 | users (seller_id, buyer_id) |
| trades | 1:N | messages |
| users | N:M | items (via wishlist) |
| sponsored_items | 독립 | 외부 광고 데이터 |

### users 테이블

> 유저 프로필 + 리프 잔액 + 뱃지 + 설정

| 컬럼 | 설명 |
|------|------|
| id | UUID PK |
| nickname | 닉네임 |
| area | 동네 (마포구 연남동) |
| leaf_balance | 리프 잔액 (INTEGER) |
| badge_level | sprout → universe |
| total_uploads / swaps / donations | 순환 통계 |
| invite_code | 내 초대 코드 (UNIQUE) |
| push_token | FCM 토큰 |
| notification_* | 알림 설정 (채팅/거래/키워드) |
| is_suspended | 정지 여부 |

### items 테이블

> 등록된 옷 정보 + 상태 관리

| 컬럼 | 설명 |
|------|------|
| id / user_id | PK + 등록자 FK |
| title / description | 상품명 + 설명 |
| category / size / condition | 카테고리 · 사이즈 · 상태 |
| trade_methods | TEXT[] — 반값택배/직거래/일반택배 |
| status | reviewing → active → reserved → swapped/donated |
| view_count | 조회수 |
| area / lat / lng | 등록 위치 |

**인덱스:** status 필터, 카테고리 필터, 유저별 조회, GIN 한글 텍스트 검색

### trades 테이블

> 거래 상태 머신 (채팅 → 예약 → 완료)

| 컬럼 | 설명 |
|------|------|
| item_id / seller_id / buyer_id | FK 관계 |
| status | chatting → reserved → completed/cancelled/reported |
| trade_method | 합의된 거래 방법 |
| report_deadline | completed_at + 48시간 |
| buyer_rating | good / bad |

### messages 테이블

> 채팅 메시지 (실시간 구독 대상)

| 컬럼 | 설명 |
|------|------|
| trade_id / sender_id | 거래방 + 발신자 |
| type | text / image / system / appointment / safety |
| content / image_url | 메시지 내용 |
| is_read | 읽음 처리 |

### 기타 테이블

| 테이블 | 설명 |
|--------|------|
| item_photos | 사진 URL (원본 + 썸네일) + 정렬 순서 |
| leaf_transactions | 리프 입출금 이력 (+1/-1, 유형, 참조 ID) |
| wishlist | 찜 목록 (user_id + item_id UNIQUE) |
| reports | 신고 (대상 유형/ID, 사유, 처리 상태) |
| notifications | 알림 (유형, 제목, 참조, 읽음 여부) |
| sponsored_items | 광고 (브랜드, 노출/클릭 카운트, 기간) |

## 5. 실시간 & 보안

### 실시간 채팅 구조 (Supabase Realtime)

Supabase Realtime의 PostgreSQL Change Data Capture를 통해 메시지와 거래 상태를 실시간으로 구독합니다.

- **💬 메시지 실시간 구독** — messages 테이블의 INSERT 이벤트를 trade_id 기준으로 필터링하여 WebSocket으로 수신. 새 메시지가 삽입되면 즉시 채팅 UI에 반영
- **🔄 거래 상태 구독** — trades 테이블의 UPDATE 이벤트를 감지. 채팅중 → 예약중 → 완료 상태 변경이 양쪽 유저에게 실시간 반영
- **✅ 읽음 처리** — 채팅방 진입 시 해당 거래의 읽지 않은 상대 메시지를 일괄 is_read = true로 업데이트

### 보안: Row Level Security

모든 테이블에 RLS가 적용되어, 클라이언트가 Supabase에 직접 접근해도 인가된 데이터만 조회/수정 가능합니다.

| 테이블 | RLS 정책 |
|--------|----------|
| users | 누구나 읽기 가능, 본인만 수정 |
| items | active 상태만 공개 읽기, 본인 아이템만 쓰기/수정 |
| messages | 거래 참여자(seller/buyer)만 접근 |
| leaf_transactions | 본인만 조회, 쓰기는 SECURITY DEFINER 함수만 |
| wishlist | 본인 데이터만 CRUD |
| notifications | 본인 알림만 접근 |

## 7. 핵심 데이터 플로우

유저 행위별 Flutter → Edge Function → DB Function → Realtime 흐름 요약

| 행위 | 플로우 |
|------|--------|
| 🔐 회원가입 | Supabase Auth → verify-invite → signup_bonus (+1리프) |
| 📸 옷 등록 | image_picker → Storage → ai-review (Gemini) + process-image (Cloudinary) → grant_leaf_for_upload (+1리프) |
| 🔍 피드 탐색 | items SELECT + 필터/정렬 → sponsor-serve (노출 기록) |
| 👁️ 상세 조회 | items + photos + users JOIN → view_count +1 |
| 💬 채팅 시작 | trades INSERT → messages INSERT → push-notify → messages 실시간 구독 시작 |
| 📨 메시지 전송 | messages INSERT → push-notify → 상대에게 Realtime 전달 |
| 📅 예약하기 | trades UPDATE → 'reserved' → push-notify → trades 구독 반영 |
| 🤝 거래 완료 | trades RPC → complete_swap (-1리프) → push-notify → trades 구독 반영 |
| 🚨 48h 신고 | reports INSERT → check-report (누적/제재 처리) |
| 🎁 기부 | items UPDATE → 'donated' → push-notify → donate_item |
| 👫 친구 초대 | 링크 공유 → 가입 시 verify-invite → process_invite (+1 양쪽) |
